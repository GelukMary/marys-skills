# PRD Writer · 需求文档

来自订阅产品付费墙与默认套餐迭代。

## 先读这个

1. **PRD 的标准不是"写完"，是研发能实现、测试能验收、上线能对账**。
2. **每个数值三件套**：默认值、是否远程配置、生效层级（新用户/全部/灰度）。
3. **每个指标必须指得到埋点**，每个埋点要能回答"谁拿它做什么决策"。
4. **禁用模糊词**："适当增加""尽量优化""视情况而定"一律改写成具体数值或规则。
5. **待定项必须有人拍板 + 期限**，不能悬空。

## 工作流

### 1. 先写两句话

- 这次要解决什么问题（附证据：数据、用户反馈、竞品）。
- 这次不做什么。

### 2. 按模板写

版本记录 → 背景与问题 → 目标与成功指标 → 范围与用户场景 → 需求详述 → 指标与埋点对账 → 异常与边界 → 待定项 → 评审记录。

### 3. 数值规则写清三层

| 项目 | 默认值 | 远程配置 | 生效层级 |
|---|---|---|---|
| 订阅页默认套餐 | 周单 | 是 | 灰度 10% → 全量 |
| 试用天数 | 3 天 | 是 | 新用户 |

### 4. 埋点对账表

指标 → 事件名 → 上报字段 → 使用方。例：付费完成率 → `pay_success` → 订单号、SKU、金额、实验组别 → 增长/产品。

### 5. 评审后升版本

修订记录、待定项回填、影响范围说明。手改过的文档只做增量修改，不整篇重写。

## 示例片段（订阅页默认套餐实验）

- 背景：默认年单，但周单占比接近 80%，说明用户更偏好低门槛。
- 假设：默认改周单可缩短决策路径，提升完成率。
- 主指标：付费完成率（支付成功÷订阅页展示）。
- 护栏：会话价值、ARPPU、退款率、取消率、续费率。
- 判定：会话价值不低于对照组 1%，完成率提升则全量。

## 常见失败

- 把需求写成功能清单，没有目标和指标。
- 只有主指标，没有护栏指标。
- 埋点名称各版本不统一，上线后对不上账。
- 待定项写着"待确认"，没人负责也没期限。
