# PRD 模板

## 一、功能模块型（每个模块六项）

| 项 | 内容要求 |
|---|---|
| 需求名称 | 一句话说清模块是什么，括号内给关键机制速览 |
| 业务流程 | 箭头串起主路径 + 旁路，标注依赖服务（= 待后端定义） |
| 原型图 | 留位，链接或截图 |
| 界面交互说明 | 逐元素编号 ①②③：文案、交互、数据来源、空值兜底 |
| 数据埋点 | pv、uv 逐条列，每条标注喂给哪个指标 |
| 特殊场景 | 异常与降级逐条编号：弱网、超时、素材缺失、服务异常、防刷 |

## 二、规格定义型（数值体系 / 接口口径）

1. 概述与设计原则
2. 名词与口径定义
3. 规格主体（计分表 / 曲线表 / 联动规则）
4. 防刷与边界
5. 展示与可见性
6. 数据规格（事件字段、远程配置清单、埋点补充）
7. 调参与迭代机制
8. 待拍板项
9. 附录（调研依据链接、相关模块 PRD 对照）

## 三、参数三件套

| 参数 | 默认值 | 是否进远程配置 | 生效层级 |
|---|---|---|---|
| 订阅页默认套餐 | 周单 | 是 | 灰度 10% → 全量 |
| 试用天数 | 3 天 | 是 | 仅新用户 |

## 四、指标 ↔ 埋点对账

| 指标 | 埋点事件 | 上报字段 | 谁用它做什么决策 |
|---|---|---|---|
| 付费完成率 | pay_success | 订单号、SKU、金额、实验组别 | 增长判断实验能否全量 |

## 五、待拍板项

| 内容 | 建议方案 | 决策人 | 影响模块 | 截止 |
|---|---|---|---|---|
| 退款后是否回收权益 | 不回收，仅标记 | 法务 + 财务 | 支付、客服 | 10/15 |
